## 1. Что за приложение

Трекер сна младенца 3–5 месяцев (сейчас 3 мес), Android, Kotlin,
Jetpack Compose, тёмная тема, русский язык. Одна главная кнопка
«Уснул / Проснулся» записывает реальное время с точностью до минуты
(через панель подтверждения с подставленным временем). Возрастная схема
(окна бодрствования, число снов, длительности) строит ПРОГНОЗ от
фактического пробуждения. Есть журнал последних 14 дней, виджет,
ночной экран, экспорт в Telegram.

## 3. Задача А — ревью корректности (приоритет)

Проверь, что приложение «точно всё считает и делает правильно». Особенно:

1. **LiveTracker.toggle/startNight/startDay/correct** — хронология, границы
   (событие ровно в предыдущее, ровно в «сейчас», ночь через полночь,
   clockTime «вчера» для будущих часов: можно ли записать событие старше
   24 ч? Требование UX-1.14: только часы/минуты, последнее прошедшее
   вхождение).
2. **forecasts()** — прогноз от факта: компенсация после короткого/длинного
   сна (±15 мин, clamp), учёт regress, конец схемы (все 4 сна отработаны —
   должен остаться «Ночной сон»), NIGHT-фаза (ночь = 1440 − Σокон − Σснов —
   не зависит от regress: осознанно или недосмотр?).
3. **History.transition/totals** — как buckets'ятся ночи (поле day =
   dayStart предыдущего подъёма): корректно ли «Прошлой ночью» на главном
   экране (MainActivity берёт maxByOrNull { it.end } из ВСЕХ NIGHT,
   не фильтруя по дню), при ночи через полночь, при «Начать заново».
4. **Полоса дня на главном** — анкер: wakeTod из state.dayStart; если день
   сдвинут (проснулся в 11:53), план строится от 09:00? Проверь логику
   выравнивания плана и факта, маркер «сейчас» (nowMin vs dayLen),
   подсветку текущего сегмента.
5. **Prefs.saveLive/loadLive** — атомарность, corrupt-флаг, undo глубиной 1.
6. **WidgetNext** — RemoteViews, setInt/setTextColor ограничения, PendingIntent.
7. **Крайние случаи**: DST-переход, смена дня во время открытой панели,
   «Отменить» после «Начать заново», повторный быстрый тап (900 мс guard),
   corrupt-сессия, пустые feeds, feeds после полуночи (nextFeed).

Формат находок: **P1 (ошибка расчёта/логики) / P2 (UX-баг) / P3 (мелочь)**,
каждая — файл:строка, сценарий воспроизведения, ожидание vs факт. Сначала
подтверди по коду, потом предлагай минимальный фикс. Всё, что меняет
математику — только в SleepEngine.kt + тесты (в проекте правило:
изменение движка без теста = баг).

## 4. Задача Б — ревью UX/UI

Смотри скриншоты (приложены к этому брифу) и/или запусти на эмуляторе
(инструкция в AI-INSTRUCTIONS.md, screen 1080×2340, density 420).

Главный экран сейчас: шапка (имя · схема, шестерёнка) → герой-карточка с
градиентом (статус, длительность, «С 09:00», подсказка нормы с полоской) →
градиентная кнопка «Уснул/Проснулся» → «Начать заново» → undo-строка →
карточка «День» (полоса дня сегментами с подписями времени и легендой,
«Ориентир» с временем, «😴 Спать осталось», «⏱ до отбоя», кормление,
плитки «Факт»: Дневной сон / Прошлой ночью / За сутки, «План дальше») →
«История по дням».

Оцени и предложи (по 1–2 строки на идею, с приоритетом):
1. Понятность полосы дня (сегменты/маркер/подсветка) — пользователь уже
   путался «тёмный кусок = спит?».
2. Плитки факта: подписи «Дневной сон / Прошлой ночью / За сутки» — ясны ли
   без объяснений; подсветка у лимитов (янтарная за 15 мин до нормы).
3. Панель записи: автофокус «Часы» с выделенным текстом, авто-переход на
   «Минуты» — достаточно ли, что ещё улучшить.
4. Визуал: градиенты, свечение кнопки, breathing-анимация — куда добавить
   «красоты» без пестроты (палитра: фон #0E1118, поверхность #161B27,
   акцент #9BB8FF, ночь #C9B8FF, предупреждение #E8C476, кормления #9FD8B4,
   Manrope).
5. Информационная иерархия: чего на экране слишком много, что свернуть.
6. Доступность: контраст, зоны нажатия, TalkBack semantics (уже есть —
   проверить полноту).

Не предлагать: облако/аккаунты, аналитику, напоминания (отказ владельца),
автоопределение сна по сенсорам, полное изменение медицинских норм.
